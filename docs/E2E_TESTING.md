# 联系方式交换端到端验证

## 目标

使用一个管理员、一个需求方和一个接单方，验证从手机号登录到接单方获得微信号的完整链路，同时验证第三方无法获得该微信号。

## 环境准备

```bash
docker compose up -d postgres redis
node --env-file=.env node_modules/prisma/build/index.js migrate deploy --schema apps/api/prisma/schema.prisma
npm run db:seed
NODE_ENV=development npm run db:seed:demo
npm run dev
```

确认：

```bash
curl -f http://localhost:4311/health/ready
```

开发环境 `.env` 需要把三个 seed 手机号加入 `DEV_LOGIN_PHONES`，验证码使用 `000000`。生产式测试应接入真实短信测试账号，禁止使用开发绕过。

## 浏览器验收步骤

分别使用三个独立浏览器上下文，避免 Cookie 串号。

### 1. 需求方

1. 使用 `13900000001 / 000000` 登录。
2. 进入个人信息，设置微信号 `printlink_alice`。
3. 发布一个真实 `.3mf` 文件并选择收货地址。
4. 确认工作台状态为“待审核”。

### 2. 管理员

1. 使用 `13800000000 / 000000` 登录。
2. 进入管理员平台的需求审核。
3. 打开刚发布的需求，确认模型可见，然后通过审核。

### 3. 接单方

1. 使用 `13900000002 / 000000` 登录。
2. 在大厅打开已审核需求。
3. 点击“申请微信联系方式”。
4. 确认按钮变为“等待需求方同意”。
5. 重复提交应得到 409，且数据库只有一条申请。

### 4. 需求方同意

1. 确认需求方通知中心收到“微信联系方式申请”。
2. 点击通知进入需求详情。
3. 在申请列表找到接单方并点击“同意并发送微信号”。
4. 重复同意应被拒绝，且只创建一条 `CONTACT_APPROVED` 通知。

### 5. 接单方获得联系方式

1. 确认接单方通知中心出现“需求方已同意你的微信申请”。
2. 确认正文只显示预期微信号 `printlink_alice`。
3. 点击通知应回到原需求详情，申请状态显示“需求方已同意”。

## 权限与隐私反向验证

- 匿名请求申请接口返回 401。
- 需求方不能申请自己的需求，返回 403。
- 第三个普通用户不能读取该需求的申请列表，返回 404。
- 第三个普通用户不能同意申请，返回 404。
- 第三个普通用户的通知列表不包含需求方微信号。
- `/api/demands` 和 `/api/demands/:id` 响应不包含 `wechatId`、收件人电话或详细地址。
- 并发发送两个同意请求，只允许一个成功，只生成一条微信通知。

## 自动化建议

新增 PostgreSQL/Redis 集成测试套件，测试时使用独立数据库 schema：

1. 写入管理员、需求方、接单方和邀请码 fixture。
2. 通过 HTTP API 获取三份独立 Cookie。
3. 上传仓库中的测试 3MF。
4. 依次调用资料、地址、需求、审核、申请、同意和通知 API。
5. 直接查询数据库断言申请数、状态、通知接收人和通知数量。
6. 使用 `Promise.allSettled` 并发调用同意接口，断言一成功一冲突。
7. 每个测试事务回滚，或在独立 schema 中测试后整体删除 schema。

CI 中应启动 PostgreSQL 16 和 Redis 7 service，先执行 `prisma migrate deploy`，再运行集成测试。只有迁移、集成测试、TypeScript、单元测试和生产构建全部通过才允许发布。
