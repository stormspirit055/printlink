# 初级联系方式撮合闭环

> 决策日期：2026-08-28 · 状态：已实现主链路

## 产品决策

当前版本放弃平台内报价、选择 Maker、生成订单、支付托管和履约跟踪。平台只把经过审核的打印需求与潜在接单方连接起来，并在需求方授权后交换微信号。

## 业务流程

```text
需求方填写微信号
  → 上传 3MF 并发布需求
  → 管理员审核通过
  → 接单方查看模型并申请微信
  → 需求方收到申请通知
  → 需求方同意
  → 接单方收到含微信号的私有通知
  → 双方在微信协商价格与履约
```

需求状态只使用：

```text
PENDING_REVIEW ──[approve]──> OPEN
       └─────────[reject]───> REJECTED
```

联系方式申请状态：

```text
PENDING ──[owner approve]──> APPROVED
```

## 事务与权限

### 创建申请

事务内完成：

1. 创建 `ContactRequest`。
2. 给需求所有者创建 `CONTACT_REQUESTED` 通知。

约束：需求为 `OPEN/QUOTED`、申请人不是需求所有者，且 `(demandId, requesterId)` 唯一。

### 同意申请

事务内完成：

1. 条件更新 `PENDING → APPROVED`。
2. 写入 `approvedAt`。
3. 给唯一申请人创建 `CONTACT_APPROVED` 通知，正文包含需求方当前微信号。

只有 `ownerId` 对应用户可以读取申请列表和同意申请。微信号不通过需求响应返回。

## 当前不做

- 拒绝或撤回申请。
- 关闭需求或标记已找到接单方。
- 要求申请人必须登记打印机。
- 在平台内报价、下单、支付、聊天、物流或评价。
- 联系方式查看历史、通知分页或导出。

## 后续可选演进

1. 增加拒绝、撤回和过期状态。
2. 需求方可关闭需求，停止新申请。
3. 申请前校验打印设备和材料/尺寸匹配。
4. 为已批准联系方式提供独立、可审计的查看入口，避免依赖最近 50 条通知。
5. 经业务验证后再决定是否恢复报价和订单能力。

## 验收

- 未填微信号不能发布需求。
- 重复申请只保留一条记录。
- 非需求方不能看到其他申请人或同意申请。
- 同意时没有微信号则拒绝。
- 并发同意只生成一次披露通知。
- 通知仅对其 `userId` 所属用户可见。
