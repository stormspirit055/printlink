# 生产数据初始化与模型访问

## 前置条件

- 已按 [数据库迁移与部署](./DATABASE_MIGRATIONS.md) 对目标数据库执行迁移，并确认应用所需表结构存在。
- 已通过部署环境注入 `DATABASE_URL`。以下命令不会自动加载项目根目录的 `.env`。
- 已确定首个管理员手机号，并确保该号码可以接收生产短信。

## 初始化基础数据

在项目根目录执行：

```bash
NODE_ENV=production npm run db:seed
```

该命令只补齐材料、颜色和计价规则，不创建用户、打印机或邀请码。重复执行不会覆盖已有计价配置；写入在一个事务中完成。

## 创建首个管理员

通过部署环境设置 `ADMIN_PHONE` 为实际管理员手机号，然后执行：

```bash
NODE_ENV=production npm run db:init-admin
```

- 空库中创建一个管理员，不设置测试微信号，也不生成固定邀请码。
- 同一手机号重复执行时返回已有管理员，不修改账号。
- 已存在其他管理员、手机号属于普通用户，或使用仓库演示手机号时，命令失败且不写入。
- 并发初始化通过数据库事务锁串行执行，避免创建两个首任管理员。
- 成功输出 `admin.bootstrap` 事件，包含时间、用户 ID 和是否创建。部署时应保存该输出作为初始化记录。

管理员随后通过真实短信登录，在后台生成正式邀请码。完成后移除部署任务中的 `ADMIN_PHONE`；服务运行不需要该变量。

## 演示数据与已有数据库

`db:seed:demo` 仅供开发或测试使用，要求显式设置 `NODE_ENV=development` 或 `test`；生产或未设置环境时会在写入前退出。

新脚本不会自动删除旧 seed 已创建的账号、设备和邀请码。已有数据库上线前需要检查 `13800000000`、`13900000001`、`13900000002` 和 `WELCOME1`，核对关联数据后单独清理。发现已有演示管理员时，先处理该账号，再执行正式初始化。

## 需求与模型访问规则

| 访问者 | `OPEN` / `QUOTED` | 其他状态 |
| --- | --- | --- |
| 未登录或会话失效 | 401 | 401 |
| 其他登录用户 | 允许 | 404 |
| 发布者或管理员 | 允许 | 允许 |

大厅仍可公开浏览已审核需求摘要。需求详情和本地模型下载遵循以上规则；本地孤儿文件不能下载，上传目录不再作为公开静态目录。详情和本地文件响应禁止缓存。

OSS 下载链接仅在需求详情权限校验通过后签发；管理员审核入口仍由管理员鉴权保护。Bucket 必须保持私有。已签发的 OSS 链接在有效期内仍可使用，无法撤回已下载的文件；上线切换时应考虑旧链接的剩余有效期并清理此前公开文件的代理缓存。
