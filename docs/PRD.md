# 印蛙 PrintLink 产品需求文档

> 版本：v2.1 · 状态：初级联系方式撮合版 · 最后更新：2026-08-28

## 1. 产品定位

印蛙是连接 3D 打印需求方与打印服务提供方的撮合平台。当前版本负责模型分析、需求发布、平台审核和联系方式交换；价格协商、付款、生产、物流、售后均由双方添加微信后在线下完成，平台不参与交易履约。

### 当前价值

| 角色   | 核心价值                                                       |
| ------ | -------------------------------------------------------------- |
| 需求方 | 上传 3MF，获得模型参数和参考价，审核通过后接收打印方的微信申请 |
| 接单方 | 浏览公开需求、查看模型与制造参数，申请需求方微信后在线下洽谈   |
| 管理员 | 审核需求，维护材料、颜色、计价规则和邀请码                     |

### 明确不包含

- 不提交或选择正式报价。
- 不生成订单，不提供支付或资金托管。
- 不跟踪生产、物流、完成、评价和争议。
- 不提供站内聊天；通知仅承载业务提醒和经授权披露的微信号。

数据库中保留的 `DemandAction`、`Quote`、`Order`、`OrderEvent`、`Review` 等模型用于未来扩展，不在当前用户业务入口中使用。当前运行时不挂载订单、支付、履约或评价接口。

## 2. 用户与准入

数据库角色只有 `USER` 和 `ADMIN`。普通用户不区分固定的买方或 Maker，同一账号可按场景发布需求或申请联系方式。

### 认证方式

- 手机号 + 6 位短信验证码登录。
- 新手机号首次登录必须提供有效邀请码。
- 不提供用户名密码注册或登录；新手机号首次登录即完成注册。
- 会话通过 30 天 HttpOnly Cookie `pl_session` 维持。

### 个人信息

用户可编辑：

- 昵称，2-30 字符。
- 微信号，1-50 字符，发布需求前必填。
- 个人简介，最多 300 字符。

微信号不出现在需求大厅或公开需求接口中，仅在需求方主动同意某一申请后写入该申请人的私有通知。

## 3. 核心业务闭环

```text
管理员发放邀请码
        ↓
用户登录并填写微信号
        ↓
需求方上传 3MF、选择地址、提交需求
        ↓
需求进入 PENDING_REVIEW
        ↓
管理员审核
  ├─ 驳回 → REJECTED
  └─ 通过 → OPEN → 进入需求大厅
                         ↓
                接单方申请微信联系方式
                         ↓
                  需求方收到通知
                         ↓
                需求方在需求详情同意
                         ↓
          系统把需求方微信号写入申请人通知
                         ↓
                  双方转至微信沟通
```

联系方式申请状态：

```text
PENDING ──[需求方同意]──> APPROVED
```

当前不提供拒绝、撤回、过期或重复授权。同一申请人对同一需求只能申请一次。

## 4. 功能要求

### 4.1 地址与需求发布

- 省、市、区采用合法行政区联动选择。
- 上传一个 `.3mf` 文件，大小受 `MAX_UPLOAD_MB` 限制。
- 浏览器解析尺寸、数量、体积、颜色，并估算重量、工时与参考价。
- 发布字段包含标题、补充要求、心理价位、地址与公开展示授权。
- 前端在进入发布流程前检查微信号，后端创建需求时再次强制校验。
- 收货信息作为需求快照保存，但不会返回到公开需求接口。

### 4.2 需求审核与大厅

- 新需求默认 `PENDING_REVIEW`。
- 管理员可通过或驳回待审核需求。
- 大厅仅列出 `OPEN`、历史遗留的 `QUOTED` 状态需求。
- 需求详情展示模型预览和制造参数。
- 当前审核结果不会主动通知需求方，需求方通过工作台查看状态。

### 4.3 联系方式申请

- 仅登录用户可申请。
- 仅 `OPEN` 或历史 `QUOTED` 需求可申请。
- 需求所有者不能申请自己的联系方式。
- 唯一约束 `ContactRequest(demandId, requesterId)` 防止重复申请。
- 创建申请与给需求方创建通知在同一数据库事务内完成。
- 只有需求所有者能读取该需求全部申请并执行同意。
- 同意使用条件更新，避免并发重复处理。
- 同意申请与创建含微信号的通知在同一事务内完成。

### 4.4 通知

- 通知列表最多返回最近 50 条，并显示未读总数。
- 支持单条已读、全部已读、15 秒轮询和 SSE 实时提示。
- 联系方式申请通知点击后跳转对应需求。
- 微信号只存在于被同意申请人的通知正文中。
- 当前没有通知分页或归档；超过最近 50 条后，旧联系方式通知无法从 UI 找回。

### 4.5 管理后台

- 查看待审核需求和远程 3MF 预览。
- 通过或驳回需求。
- 编辑材料、颜色和计价规则。
- 创建、查看、停用邀请码。

## 5. 数据模型

| 模型                                       | 当前用途                                   |
| ------------------------------------------ | ------------------------------------------ |
| `User`                                     | 账号、角色、昵称、微信号、简介             |
| `InvitationCode`                           | 邀请注册配额、有效期和停用状态             |
| `Session`                                  | 登录会话                                   |
| `ShippingAddress`                          | 用户收货地址                               |
| `Printer`                                  | 用户登记的打印设备；当前不作为申请前置条件 |
| `Material` / `ColorOption` / `PricingRule` | 模型估价配置                               |
| `Demand`                                   | 需求、模型参数、收货快照、审核状态         |
| `ContactRequest`                           | 联系方式申请及同意状态                     |
| `Notification`                             | 业务提醒和授权后的微信号披露               |

## 6. 安全与隐私

- 微信号不得通过公开用户、需求列表或需求详情额外暴露。
- 联系方式申请列表仅需求所有者可读取。
- 同意操作仅申请记录的 `ownerId` 可执行。
- 通知按当前登录用户 `userId` 过滤。
- 会话令牌只存哈希；生产 Cookie 使用 `Secure`。
- CORS 只允许配置的 `WEB_ORIGIN` 并携带凭证。
- 日志脱敏 Cookie、密码和邀请码；手机号、验证码不得作为结构化日志字段输出。

## 7. 验收标准

1. 新用户使用邀请码完成首次登录并填写微信号。
2. 未填写微信号时前后端均阻止发布需求。
3. 需求提交后进入待审核，管理员通过后进入大厅。
4. 非所有者能提交一次联系方式申请，需求方收到通知。
5. 非所有者不能查看申请列表或同意申请。
6. 需求方同意后，只有对应申请人的通知包含当前微信号。
7. 重复申请、重复同意和并发同意不会生成重复授权通知。
8. 页面在移动端、桌面端和明暗主题下可用。
9. 生产部署完成迁移，API `/health/ready` 可用。

## 8. 当前上线结论

业务代码已覆盖“手机号用户登录 → 填微信 → 发布 → 审核 → 申请 → 同意 → 私有通知披露微信号”的主链路，但仓库当前不能按默认生产部署直接上线。完整风险和阻塞项见 `docs/PRODUCTION_READINESS.md`。
